# Ludoteca Implementation Plan

**Goal:** consegnare tutti i requisiti di `AGENT.md`, senza commit automatici.
**Architecture:** Next.js App Router stateless; PostgreSQL ospitato su Supabase, accessibile solo dal server con utente dedicato. Lock transazionale globale per tutte le mutazioni che incidono sulla sala, con controllo sovrapposizioni e capienza. Supabase Auth con allowlist UUID amministratori, Resend e Storage privi di segreti client.
**Spec:** `AGENT.md` (requisiti congelati).

## Contratti

API JSON, errori `{error:string}`, date ISO UTC e rappresentazione Europe/Rome. `GET /api/games`, CRUD admin `/api/admin/games`; gioco `{id,title,minPlayers,maxPlayers,duration,complexity,description,images:string[],bggUrl,archived}`. `GET /api/settings` e `PUT /api/admin/settings`: `{roomCapacity,tables:[{id,name,seats}],openingDays:number[],openTime,closeTime,slotMinutes}`. Domenica=0. `GET /api/availability?date=YYYY-MM-DD`: `{slots:[{start,end,tables:[{id,name,seats,available}],remainingCapacity}]}`. `POST /api/bookings`: `{email,participants:string[],tableId,start,end,website?:string}`. Risposta solo `{ok:true}`, link esclusivamente email. Gestione token nel fragment `/manage#TOKEN`; client POST `/api/manage` con `{token,action:'read'|'update'|'cancel',booking?:{tableId,start,end,participants}}`; lettura privata `{booking}`. Admin `GET /api/admin/bookings` restituisce `{bookings}`, `PATCH /api/admin/bookings` con `{id,status}`. Login POST `/api/auth/login` `{email,password}`, logout POST `/api/auth/logout`; cookie HttpOnly e verifica server su ogni endpoint admin. Health `GET /api/health`.

## Fasi e verifiche

1. Fondazione: configurazioni, dipendenze, contratti e test runner. Verifica installazione e TypeScript.
2. Backend (agente dedicato): test validazione, transizioni, token e concorrenza prima dell'implementazione; migrazione, servizi transazionali, API, autenticazione, rate limit condiviso DB, provider email. Verificare con Vitest e PostgreSQL Docker reale.
3. UI (agente dedicato): catalogo con ricerca/filtri e schede, calendario e richiesta, gestione link privato, login, admin CRUD e impostazioni. Verificare con Playwright desktop/mobile, errori e axe.
4. Integrazione: eseguire typecheck, tutti i test, build e correggere fino a esito positivo. Revisione indipendente di autorizzazioni, privacy e transazioni.
5. Operativita: Docker multi-stage non-root, healthcheck; `.env.example`, README e istruzioni Coolify/Supabase/Resend/Funnel. Build/avvio reale Docker e riepilogo onesto delle verifiche.

## Assunzioni

Sala iniziale 12 posti; tre tavoli da 2/4/6. Apertura martedi-domenica 18:00-24:00, fasce 120 minuti; timezone Europe/Rome, orari configurabili. Nessuna scadenza pending. Token riutilizzabile finche la prenotazione e attiva; dopo cancellazione lettura ancora ammessa, mutazioni vietate. Giochi archiviati anziche cancellati. Email fallita non annulla una prenotazione: outbox persistente e retry autenticato. Non inserire cataloghi fittizi in produzione.
